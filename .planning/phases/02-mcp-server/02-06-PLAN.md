export function createServer(): McpServer {
  const server = new McpServer({ name: "talos-mcp", version: "1.0.0" });

  registerSearchTool(server);
  registerUpdateTool(server);
  registerDeleteTool(server);

Set up Origin validation middleware (applied before authMiddleware):
```typescript
function originGuard(req, res, next) {
  const origin = req.headers["origin"];
  if (origin) {
    // If Origin header present, it must be from an allowed origin
    const allowed = (process.env.ALLOWED_ORIGINS ?? "").split(",").filter(Boolean);
    if (!allowed.includes(origin)) {
      res.status(403).json({ error: "ORIGIN_REJECTED", message: "Origin not allowed" });
      return;
    }
  }
  // No Origin header = direct API call = allowed
  next();
}
```

Apply middleware order on /mcp: `originGuard` → `authMiddleware` → transport handler.

**mcp/Dockerfile:**

Use Node 20 Alpine. No build step — tsx executes TypeScript directly.

```dockerfile
FROM node:20-alpine

WORKDIR /app

# Install dependencies first (layer cache)
COPY package.json package-lock.json ./
RUN npm ci --omit=dev && npm install tsx

COPY src/ ./src/

# Health check via /health endpoint
HEALTHCHECK --interval=15s --timeout=5s --start-period=10s --retries=3 \
  CMD wget -qO- http://localhost:3000/health || exit 1

EXPOSE 3000

CMD ["node", "--loader", "tsx/esm", "src/transport.ts"]
```

Note: Using `node --loader tsx/esm` rather than `npx tsx` avoids npx overhead in production. Alternatively use `./node_modules/.bin/tsx src/transport.ts` if loader flag causes issues with the Node version.

**docker-compose.yml:**

Read the existing docker-compose.yml from Phase 1 (it defines: postgres service, backend network, frontend network, agent_keys secret, postgres_data volume). Add the mcp service to it — do NOT remove or modify existing services.

Add to services:
```yaml
  mcp:
    build: ./mcp
    restart: unless-stopped
    networks:
      - backend
      - frontend
    secrets:
      - agent_keys
    environment:
      DATABASE_URL: "postgresql://mcp_service:${MCP_SERVICE_PASSWORD}@postgres:5432/talos"
      EMBEDDING_PROVIDER: "${EMBEDDING_PROVIDER:-openrouter}"
      EMBEDDING_MODEL: "${EMBEDDING_MODEL:-openai/text-embedding-3-small}"
      EMBEDDING_API_KEY: "${EMBEDDING_API_KEY}"
      VECTOR_DIMENSIONS: "${VECTOR_DIMENSIONS:-1536}"
      CHUNK_SIZE: "${CHUNK_SIZE:-2000}"
      CHUNK_OVERLAP: "${CHUNK_OVERLAP:-200}"
      ALLOWED_ORIGINS: "${ALLOWED_ORIGINS:-}"
      PORT: "3000"
    depends_on:
      postgres:
        condition: service_healthy
    healthcheck:
      test: ["CMD", "wget", "-qO-", "http://localhost:3000/health"]
      interval: 15s
      timeout: 5s
      retries: 3
      start_period: 15s
```

The mcp service is on BOTH networks: `backend` (to reach postgres) and `frontend` (agents reach MCP on this network). This enforces the Phase 1 topology: agent containers can only reach MCP via frontend, never reach postgres directly.

`MCP_SERVICE_PASSWORD` env var must be set in the Docker secrets / .env that Phase 1's setup.sh generates — add a note in the file comment if setup.sh needs updating for this credential.
