  <name>Task 1: Implement update tool (MCP-03)</name>
  <files>mcp/src/tools/update.ts</files>
  <behavior>
    - update({ id, content: "new text" }) → deletes old chunks, re-embeds new content, writes new chunks, updates entries.content and entries.updated_at — all in one transaction
    - update({ id, metadata: { tag: "y" } }) with no content → updates metadata JSONB only, no re-embed, updated_at updated
    - update({ id, content: "text", metadata: {...} }) → does both content replace + metadata update in same transaction
    - update with id that does not exist (or belongs to different agent) → returns toolError("NOT_FOUND", "Entry not found or access denied")
    - update with empty content → returns toolError("VALIDATION_ERROR", "Content must not be empty")
    - Embedding failure during update → rolls back entire transaction, entry remains unchanged
    - update returns {id, content, path} on success; verbose: true adds {metadata, updated_at, chunk_count}
  </behavior>

**Handler logic for content update path:**
1. Validate: content present and non-whitespace-only
2. Read chunk config from env (same defaults as insert: CHUNK_SIZE=2000, CHUNK_OVERLAP=200)
3. Chunk new content, embed all chunks (outside transaction — embedding is slow)
4. Open `withAgent(agentId, async (client) => { ... })`:
   a. `DELETE FROM chunks WHERE entry_id = $1` — removes old chunks
   b. `UPDATE entries SET content=$2, updated_at=NOW() WHERE id=$1 RETURNING id, content, path` — if 0 rows: throw NOT_FOUND
   c. If metadata provided: `UPDATE entries SET metadata=$2 WHERE id=$1`
   d. INSERT new chunks
5. Build response

**Handler logic for metadata-only path** (no content):
1. Open `withAgent()`:
   a. `UPDATE entries SET metadata=$2, updated_at=NOW() WHERE id=$1 RETURNING id, content, path` — if 0 rows: throw NOT_FOUND
2. Build response

Log: `{operation: "update", agent_id, entry_id, content_updated: !!content, metadata_updated: !!metadata, duration_ms}`

**Handler logic:**
1. Open `withAgent(agentId, async (client) => { ... })`:
   a. `DELETE FROM entries WHERE id=$1 RETURNING id` (RLS on agent_id filters automatically)

   c. Return `{ content: [{ type: "text", text: JSON.stringify({ deleted: id }) }] }`

DO NOT return the deleted content in the response — just the id confirmation.

Log: `{operation: "delete", agent_id, entry_id, duration_ms}`

Note: chunks are deleted by ON DELETE CASCADE defined in Phase 1 schema — no explicit chunk DELETE needed.
