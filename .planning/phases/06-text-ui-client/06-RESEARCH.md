## Summary

Phase 6 builds a full-featured terminal UI client using Ink (React for CLIs) on the host side, backed by a new Express HTTP API added to the agent container. The most architecturally significant work is refactoring `providers/claude.ts` from a collect-and-return model to a streaming event model, so SSE events can flow from the Anthropic stream through the agent to the TUI in near-real-time.

The Ink ecosystem (v6.8.0) is mature and well-suited for this use case. React 19 and Node 22 are required. The ecosystem has first-party components for text input (ink-text-input v6) and select menus (ink-select-input v6), though both were built against Ink v5 — they should work with Ink v6 since React 19 is broadly backward-compatible with React 18 component code, but this should be verified early in Wave 0. Scrolling is a manual implementation concern in Ink — there is no built-in scrollable container. The pattern is to track a scroll offset in state and slice the messages array to fit the terminal height.

SSE transport is the right choice for streaming: Express serves the event stream with `text/event-stream` content type, and on the TUI side a Node.js-compatible fetch-based SSE client handles the connection. The native browser `EventSource` does not support custom headers (required for Bearer token auth), so a fetch-based approach is required — either `@microsoft/fetch-event-source` or a manual `fetch()` with `ReadableStream` parsing.

**Primary recommendation:** Target Ink v6 + React 19 + Node 22. Implement SSE consumer using `fetch()` with a simple stream parser rather than `EventSource`. Implement scrolling manually with `useWindowSize` + state offset. Start by refactoring `claude.ts` to emit stream events — this is the blocking dependency for everything else.

### Pattern 1: Express SSE Stream (Agent Side)
**What:** Express endpoint sets SSE headers, holds response open, writes events as the agent processes.
**When to use:** All agent-side streaming output.

```typescript
// Source: SSE spec + Express 5 docs
app.get('/chat/stream', authMiddleware, (req, res) => {
  // Reject second client
  if (activeSession) {
    res.status(409).json({ error: 'SESSION_ACTIVE' });
    return;
  }

  res.setHeader('Content-Type', 'text/event-stream');
  res.setHeader('Cache-Control', 'no-cache');
  res.setHeader('Connection', 'keep-alive');
  res.flushHeaders();

  activeSession = { res };

  req.on('close', () => {
    activeSession = null;
  });
});

function sendEvent(type: string, data: unknown): void {
  if (!activeSession) return;
  activeSession.res.write(`event: ${type}\ndata: ${JSON.stringify(data)}\n\n`);
}
```

### Pattern 2: Fetch-Based SSE Consumer (TUI Side)
**What:** Node 22 native `fetch()` with streaming body, parsed line-by-line into SSE events. Supports Bearer token header (which native `EventSource` does not).

```typescript
// Source: Node.js fetch + SSE wire format
async function* streamSSE(url: string, token: string): AsyncGenerator<SSEEvent> {
  const resp = await fetch(url, {
    headers: { Authorization: `Bearer ${token}`, Accept: 'text/event-stream' },
  });
  if (!resp.ok || !resp.body) throw new Error(`SSE connect failed: ${resp.status}`);

  const reader = resp.body.getReader();
  const decoder = new TextDecoder();
  let buffer = '';
  let eventType = 'message';

  while (true) {
    const { done, value } = await reader.read();
    if (done) break;
    buffer += decoder.decode(value, { stream: true });
    const lines = buffer.split('\n');
    buffer = lines.pop() ?? '';

    for (const line of lines) {
      if (line.startsWith('event:')) {
        eventType = line.slice(6).trim();
      } else if (line.startsWith('data:')) {
        yield { type: eventType, data: line.slice(5).trim() };
        eventType = 'message';
      }
    }
  }
}
```

### Pattern 4: Ink Scrollable Chat
**What:** No built-in scroll in Ink. Track `scrollOffset` (number of messages scrolled up) in state. Compute `visibleMessages` by slicing from the end.

```typescript
// Source: Ink docs — useWindowSize + manual state management
const { rows } = useWindowSize();
const chatHeight = rows - HEADER_HEIGHT - STATUS_HEIGHT - INPUT_HEIGHT;

// Messages to render (most recent N that fit)
const visibleMessages = scrollOffset === 0
  ? messages.slice(-chatHeight)
  : messages.slice(-(chatHeight + scrollOffset), messages.length - scrollOffset);
```

### Pattern 6: Bearer Token Auth Middleware (Agent HTTP Server)
Reuse `mcp/src/auth.ts` pattern — but adapted for a single TUI token rather than a map of agent keys. The TUI token lives in a new Docker secret `tui_token`.

```typescript
// Adapted from Phase 2 pattern (mcp/src/auth.ts)
function loadTuiToken(): string {
  return fs.readFileSync('/run/secrets/tui_token', 'utf8').trim();
}

export function tuiAuthMiddleware(req: Request, res: Response, next: NextFunction): void {
  const auth = req.headers.authorization;
  if (!auth?.startsWith('Bearer ') || auth.slice(7) !== tuiToken) {
    res.status(401).json({ error: 'AUTH_REQUIRED' });
    return;
  }
  next();
}
```

### Anti-Patterns to Avoid
- **Using browser `EventSource` for SSE:** Does not support custom request headers, so Bearer token cannot be sent. Use `fetch()` streaming instead.
- **Starting Express in a separate process:** The agent HTTP server must share `conversationHistory` and `startAgentLoop` with the readline loop. Both run in the same `entrypoint.ts` process.
- **Blocking the readline interface while SSE is streaming:** The readline and HTTP paths must coexist — `rl.on('line')` is async and non-blocking; Express operates on Node's event loop naturally.
- **Building Ink components with `process.stdout.write`:** All terminal output must go through Ink's renderer. Direct writes corrupt the layout.
- **Re-rendering all messages on every token:** Use React state so only the in-progress message component re-renders. Keep the messages array stable and append-only.

## Don't Hand-Roll

| Problem | Don't Build | Use Instead | Why |
|---------|-------------|-------------|-----|
| Text cursor, backspace, paste handling | Custom input loop | ink-text-input | IME, cursor navigation, pasted text highlighting already handled |
| Terminal layout (rows/cols) | Manual ANSI math | Ink Box + useWindowSize | Yoga flexbox, automatic reflow on resize |
| Spinner animation | setInterval + ANSI writes | ink-spinner | Timer management, cleanup, no flicker |
| Markdown to ANSI | Custom escape sequences | marked + marked-terminal | Code highlighting, all block types, tested against terminal edge cases |
| Select dropdown | Custom arrow-key handler | ink-select-input | Focus management, scroll within list, keyboard handled |
| SSE wire format parsing | Custom regex | inline 20-line parser (see Pattern 2) | The format is simple enough that a purpose-built inline parser is cleaner than a dependency |

**Key insight:** The "display" layer (markdown, spinners, input) has robust Ink ecosystem solutions. The "plumbing" layer (SSE parsing, scroll offset) is simple enough to implement inline without a library.

## Common Pitfalls

### Pitfall 1: Ink v6 peerDep mismatch with ecosystem packages
**What goes wrong:** `ink-text-input@6` and `ink-select-input@6` declare `peerDependencies: { ink: ">=5", react: ">=18" }` but Ink v6 requires `react@>=19`. npm may print peer conflict warnings; in strict mode (`npm install` without flags), it may refuse to install.
**Why it happens:** Ink v6 shipped January 2025 and ecosystem packages have not updated peer ranges yet.
**How to avoid:** Verify compatibility in Wave 0. If warnings-only, proceed. If hard block, use `--legacy-peer-deps` or pin to `ink@5.x` (which requires `react@>=18` and is more stable for the ecosystem).
**Warning signs:** npm install exits non-zero with `ERESOLVE` on the tui/ package.

### Pitfall 2: SSE connection blocked by agent container security profile
**What goes wrong:** The agent container uses `read_only: true`, `cap_drop: ALL`, and a custom seccomp profile. Adding an Express server that binds a port requires no new capabilities, but the seccomp profile must allow the `listen`/`accept` syscalls Express needs.
**Why it happens:** The seccomp profile (`agent/seccomp-standard.json`) is the Docker default v28 profile — it does allow TCP listen. But adding port 3001 means `docker-compose.yml` needs a `ports:` mapping on the agent service.
**How to avoid:** Add `ports: - "${AGENT_API_PORT:-3001}:3001"` to the agent service in compose. Verify the seccomp profile includes `bind`, `listen`, `accept4`, `getsockname` — the Docker default profile includes all of these.
**Warning signs:** Express `listen` throws EACCES or server never becomes reachable.

### Pitfall 3: Anthropic SDK streaming vs. non-streaming API shape
**What goes wrong:** `messages.create()` returns `Message`. `messages.stream()` returns a `MessageStream`. These are different types. The existing `runClaudeLoop` accumulates `response.content` from `Message` — the streaming refactor must use the `MessageStream` event API.
**Why it happens:** The team is switching from batch to streaming mid-loop without changing the loop structure.
**How to avoid:** Use `client.messages.stream(params).on('text', cb)` or `for await (const event of stream)` to consume `RawMessageStreamEvent`. Accumulate text and tool_use blocks incrementally.
**Warning signs:** `stream.finalMessage()` is needed to get the complete `stop_reason` and `usage` at the end.

### Pitfall 4: Multiple concurrent SSE writes from tool call parallelism
**What goes wrong:** `runClaudeLoop` calls multiple MCP tools sequentially per turn, but if they were parallelized in future, concurrent `sendEvent()` calls could interleave SSE frames.
**Why it happens:** SSE requires newline-delimited framing; partial writes could corrupt the stream.
**How to avoid:** Keep tool calls sequential (already the case). Add a guard that ensures `sendEvent` is called from the event loop only — never from concurrent async paths.
**Warning signs:** TUI parser receives malformed event data (JSON.parse throws).

### Pitfall 5: Terminal height calculation off-by-one
**What goes wrong:** Chat area height is wrong, causing the last message to be cut off or too much blank space.
**Why it happens:** `useWindowSize()` returns the full terminal `rows`. The layout has fixed-height header, status bar, and input bar. Their exact row heights must be tracked as constants and subtracted accurately.
**How to avoid:** Define `HEALTH_BAR_HEIGHT = 1`, `STATUS_BAR_HEIGHT = 1`, `INPUT_BAR_HEIGHT = 1` as constants. Chat area height = `rows - HEALTH_BAR_HEIGHT - STATUS_BAR_HEIGHT - INPUT_BAR_HEIGHT`.
**Warning signs:** Messages overflow or blank space visible below the last message.

### Pitfall 6: `./talos chat` calling `docker exec` vs. running tui on host
**What goes wrong:** The TUI runs on the host (not in the container) but needs to launch against the running agent container. `./talos chat` should run `node tui/dist/app.js` as a host process — but the tui build must exist.
**Why it happens:** No install/build step is documented yet; `./talos chat` might fail if `tui/dist/app.js` doesn't exist.
**How to avoid:** Add a tui build step to the setup process or add a check in `./talos chat` that prints a helpful error if `tui/dist/app.js` is missing.
**Warning signs:** `node tui/dist/app.js` exits with "Cannot find module".

### SSE Express route with session guard
```typescript
// Agent side — http-server.ts
// Source: SSE spec + Express patterns
let activeSession: { res: Response } | null = null;

app.post('/chat/message', tuiAuthMiddleware, express.json(), async (req, res) => {
  if (!activeSession) {
    res.status(409).json({ error: 'NO_SESSION', message: 'Open /chat/stream first' });
    return;
  }
  const { message } = req.body as { message: string };
  // Fire-and-forget: don't await — response streams via SSE
  void processMessage(message);
  res.status(202).json({ queued: true });
});

app.get('/chat/stream', tuiAuthMiddleware, (req, res) => {
  if (activeSession) {
    res.status(409).json({ error: 'SESSION_ACTIVE' });
    return;
  }
  res.setHeader('Content-Type', 'text/event-stream');
  res.setHeader('Cache-Control', 'no-cache');
  res.setHeader('Connection', 'keep-alive');
  res.flushHeaders();
  activeSession = { res };
  req.on('close', () => { activeSession = null; });
});
```

## Open Questions

1. **ink-text-input / ink-select-input compatibility with Ink v6 + React 19**
   - What we know: Both packages declare `peerDependencies: { ink: ">=5" }`. Ink v6 requires React 19.
   - What's unclear: Whether peer resolution causes a hard npm install failure or only a warning.
   - Recommendation: Test `npm install ink@^6 react@^19 ink-text-input@^6` in Wave 0. If hard fail, fall back to Ink v5 (React 18) — all other patterns remain the same.

2. **Anthropic SDK extended thinking streaming**
   - What we know: The SDK's `.stream()` emits `thinking_delta` events when extended thinking is enabled.
   - What's unclear: Whether the current `AGENT_LLM_MODEL` (claude-sonnet-4-6) exposes extended thinking via the stream API, or whether a `betas: ['interleaved-thinking-2025-05-14']` header is required.
   - Recommendation: Treat thinking blocks as optional — emit them when present, render ThinkingBlock only if events arrive. This gracefully degrades if thinking is not enabled.

3. **`/btw` soft-interrupt injection mechanism**
   - What we know: The `/btw` command should inject a message into the agent's agentic loop mid-processing.
   - What's unclear: The agent loop runs as a sequential `for` loop in `runClaudeLoop`. There is no hook point between tool calls. The `/btw` message would need to be queued and injected as an additional user turn after the current turn completes, or the loop would need to be made interruptible (cooperative pause between turns).
   - Recommendation: Implement as "inject after current turn" — the `/btw` message is held in a queue on the session, and the loop checks for queued messages after `stop_reason === 'end_turn'` before returning. This is safe and avoids mid-stream state corruption.
