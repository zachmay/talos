# Phase 6: Text UI Client - Context

**Gathered:** 2026-03-28
**Status:** Ready for planning

<domain>
## Phase Boundary

Terminal-based TUI for interactive agent conversations, replacing the raw readline REPL. Delivers a host-side Ink (React) client that connects to the agent container via HTTP+SSE, with chat view, input area, status indicators, and infrastructure health display. Also adds an Express HTTP API to the agent container for TUI communication.

</domain>

<decisions>
## Implementation Decisions

### TUI Framework & Architecture
- **Ink (React-based)** terminal UI framework for the client
- **Host-side client** in new `tui/` top-level directory (separate package.json, own build)
- Agent container gets an **Express HTTP server** alongside the existing readline loop (both run in same process, share conversation state)
- Communication via **HTTP + Server-Sent Events (SSE)** — agent streams thinking/tool/token events as distinct SSE event types
- No Docker attach support — HTTP-only transport (works local and remote with same code path)
- **Shared types** in `shared/` directory for API contracts (SSE events, request/response shapes) — both agent and tui import via relative path
- Entry point: `./talos chat` (subcommand on existing CLI wrapper), runs `node tui/dist/app.js` under the hood
- Supports `--host` and `--token` flags for remote connections
- Repo-local for MVP — no npm global install, no separate package publishing
- **Single session** — one TUI client at a time, second client gets rejected (409)
- Agent API port: **3001 default**, configurable via `AGENT_API_PORT` env var
- Bind address configurable via `AGENT_API_HOST` (default `0.0.0.0`, set `127.0.0.1` to lock to localhost)
- Port always exposed in compose (no profile gating) — bearer token required regardless

### Authentication
- **New dedicated TUI access token** generated by `./talos setup` (same generation pattern as agent API keys from Phase 2, stored as Docker secret)
- TUI passes token via `--token` flag or `TALOS_AGENT_TOKEN` env var
- Agent validates `Authorization: Bearer <token>` on all HTTP endpoints

### Chat Display
- **Markdown rendered** responses — bold, italic, code blocks with syntax highlighting (marked-terminal or ink-markdown)
- **Labeled + colored** messages — "You:" (green) and "Agent:" (blue) prefixes
- **Spacing only** between conversation turns (no divider lines)
- **Dimmed relative timestamps** on each message (e.g., "2m ago" or "12:34")
- Agent response metadata: turns and token count shown after each response
- **Smart auto-scroll** — auto-scrolls if at bottom, stays put if scrolled up, "New messages below" indicator when pinned up
- No in-chat search for MVP

### Thinking Display
- **Collapsible dimmed block** appears as soon as thinking starts (collapsed by default)
- If expanded mid-stream, shows all thinking text so far plus live streaming of new content
- If left collapsed, only the indicator shows (with bottom spinner for activity)
- Expanding after completion shows full thinking text statically

### Tool Call Display
- **Stacked inline badges** — each tool call on its own line, appearing as they execute
- Format: `> tool_name "query" → result_summary`
- **Expandable** — key/click to expand a badge and see full request params and response (same collapsible pattern as thinking blocks)

### Input Experience
- **Single-line input**, expandable to multi-line via Shift+Enter
- **Enter sends**, Shift+Enter for newline
- **Up/Down arrows** cycle through previous messages (session history)
- **Tab-complete** for slash commands (popup suggestion list)
- **Smart paste** — detect bracketed paste, auto-expand to multi-line for pasted code blocks
- **Input stays active** while agent processes — normal messages queue for after response
- **`/btw <message>`** — soft-interrupt: injects message into agent's current agentic loop between turns. Agent continues its chain but now has the new context
- **Ctrl+C** stops current response; double Ctrl+C (or /quit) exits TUI

### Slash Commands
Client-side (never sent to agent):
- `/quit` — exit TUI, close connection
- `/clear` — reset conversation history (tells agent to clear too)
- `/status` — show connection info, context %, model, profile, token usage
- `/help` — list all available commands
- `/reconnect` — drop and re-establish SSE connection

Agent-side (sent as special messages):
- `/skills` — list available skills
- `/history` — show conversation turn count and token summary

Unknown `/` commands show "Unknown command. Type /help for options."

### Keyboard Shortcuts
- Ctrl+C — stop response / quit
- Ctrl+L — clear chat view
- Esc — collapse expanded multi-line input
- Tab — autocomplete /commands
- Up/Down — message history
- Shift+Enter — newline in input
- PgUp/PgDn — scroll chat

### Layout
- **Top:** Infrastructure health indicators (DB, MCP, LLM, Embed) — colored dots (green=local, yellow=cloud)
- **Middle:** Scrollable chat area
- **Bottom status line:** Connection indicator, agent profile, model name, context % (mini progress bar), token count
- **Bottom input:** `> _` prompt
- **Context progress bar:** Mini bar with 4-tier color — green (<50%), yellow (50-70%), orange (70-85%), red (>85%)
- Token count always visible in status bar (updates after each turn)
- **Responsive** — reflows on terminal resize (Ink handles natively)

### Status & Health
- Infrastructure health via `./talos health --json` — TUI polls every 30 seconds in background
- Also refreshes on startup, /reconnect, /status
- Connection status indicator: Connected (green) / Reconnecting (yellow) / Disconnected (red)
- Auto-reconnect on disconnect with visual feedback

### Activity Indicators
- **Bottom spinner** in chat area while agent is processing
- **Turn count** shown in spinner: "Processing... (turn 3)"
- **Terminal bell** (BEL character) when agent completes a response (triggers tab badge / sound in most terminals)

### Startup
- Brief welcome message in chat area: "Connected to {profile} ({model}). Type /help for commands."
- No theming for MVP — one color scheme that works on dark and light terminals

### Claude's Discretion
- Exact Ink component architecture and file structure within tui/
- SSE event schema design (field names, payload structure)
- Express route design for the agent HTTP API
- Markdown rendering library choice (marked-terminal vs ink-markdown vs other)
- Activity spinner implementation
- Auto-reconnect retry strategy (backoff, max attempts)
- How /btw injection interacts with the Claude provider's agentic loop
- How to refactor providers/claude.ts from collect-full-response to stream-events

</decisions>

<specifics>
## Specific Ideas

- Infrastructure health indicators inspired by dashboard-style colored dots: green for local connections, yellow for cloud/managed sources
- /btw soft-interrupt: allows injecting context into the agent's current processing chain without stopping it — "keep doing what you were doing but here's some fresh input"
- Thinking blocks behave like a live log: collapsed by default, expand to watch thinking stream in real-time
- The agent HTTP API coexists with readline — both interfaces work from the same process and conversation state

</specifics>

## Existing Code Insights

### Reusable Assets
- `agent/src/entrypoint.ts`: Current readline loop — HTTP server runs alongside it, sharing `conversationHistory` and `startAgentLoop()`
- `agent/src/providers/claude.ts`: `LoopResult` interface (text, inputTokens, outputTokens, contextLimit, turns) — needs refactor to stream events instead of collecting full response
- `agent/src/prompt.ts`: System prompt loader + skill index builder — reused by HTTP handler
- `scripts/health.sh`: Already outputs health data with `--json` flag — TUI parses this directly
- `./talos` CLI wrapper: Add `chat` subcommand routing to `node tui/dist/app.js`
- `renderPrompt()` in entrypoint.ts: Shows context %, model, profile — status bar replaces this

### Established Patterns
- Phase 2: Express HTTP server pattern in MCP server (`mcp/src/index.ts`)
- Phase 2: Bearer token authentication middleware (`mcp/src/auth.ts`)
- Phase 3: Provider-agnostic agent loop with tool call handling
- Phase 4: `./talos` CLI wrapper with subcommand routing
- Phase 4: `--json` flag for machine-readable output

### Integration Points
- `agent/src/entrypoint.ts` — add Express server alongside readline
- `agent/package.json` — add express dependency
- `docker-compose.yml` — expose port 3001 on agent container
- `./talos` wrapper — add `chat` subcommand
- `./talos setup` — generate TUI access token
- `shared/` — new directory for API contract types (imported by both agent/ and tui/)
- `tui/` — new top-level directory for TUI client

</code_context>

- **Mutual TLS (mTLS)** — client certificate auth for hardened remote deployments
- **`/export` command** — save session to markdown/JSON file
- **Chat search (Ctrl+F)** — search/filter messages in current session
- **Theming / color customization** — dark/light auto-detect, custom color schemes
- **npm global install** — publish tui as standalone package for use without repo checkout
- **Multiple concurrent sessions** — multiple TUI clients connected to same agent

</deferred>
